# Grid Splitter

A small tool for slicing an image into an even grid. Supports cropping, live preview and lossless output. Everything runs **entirely on your own machine — images are never uploaded to any server**.

[中文说明 / Chinese documentation](README.zh-CN.md)

Two versions are provided:

- **Web version** — just double-click `index.html`. No installation, no internet connection required.
- **CLI version** — for batch processing or automation pipelines.

## Web version

Double-click `index.html`, or open it in any browser.

### Features

| Feature | Description |
|---|---|
| Drag & drop upload | Click or drag images onto the canvas; JPG / PNG / WebP, multiple at once |
| Paste upload | Press `Ctrl+V` to paste an image from the clipboard |
| Crop box | Enable "Crop area" and drag the box to slice only the selected region; eight handles to resize |
| Crop shape | **Free** (any rectangle) / **Square** / **Fixed ratio** (e.g. 4:3, 16:9) |
| Exact equal tiles | Automatically nudges the crop size to a multiple of the row/column count so every tile is pixel-identical |
| Live grid | Grid lines and tile numbers update instantly as you change parameters |
| Three split modes | Equal division / fixed pixel size / custom ratios |
| Lossless PNG | Outputs PNG, byte-for-byte lossless; turn it off for JPEG with adjustable quality |
| Remainder output | In fixed-size mode, the leftover edge strips are exported separately |
| ZIP packaging | One click packages all tiles into a ZIP, auto-named by row and column |

### Crop shapes

Once "Crop area" is enabled, three shapes are available:

| Shape | Use case |
|---|---|
| Free | Any aspect ratio, drag freely |
| Square | Forced 1:1 — avatars, square social media posts |
| Ratio | Locks to a given ratio. Presets: 1:1, 4:3, 3:4, 16:9, 9:16; you can also type e.g. `3:2` |

**How the square is guaranteed**: the crop box is stored in normalized coordinates internally,
but equal *normalized* width and height does **not** mean equal *pixels*.
For example, on a 1773×2364 portrait image, a normalized width of 0.5 maps to 886 px while a
normalized height of 0.5 maps to 1182 px. The constraint is therefore computed against the
**actual image pixels**, guaranteeing the cropped result is a true pixel-level square.

### Exact equal tiles

When the cropped size is not divisible by the row/column count (e.g. 1330 split 3×3), the tool
**automatically nudges** the crop size to the nearest divisible value (1330 → 1329) so that
every tile is pixel-identical. The UI reports the actual adjustment. Turn the switch off if you
prefer the 1-pixel variance.

Note: when "Crop area" is unchecked, no adjustment is made — the full original image is
sliced. Custom-ratio mode is also left untouched so your specified ratios are preserved.

### Keyboard shortcuts

| Key | Action |
|---|---|
| `Ctrl+V` | Paste an image from the clipboard |
| Hold `Shift` while dragging | Temporarily lock to a square in Free mode; lock the original ratio when resizing an existing box |

## Using it on a phone

This tool works in mobile browsers — no app installation required.

### Recommended: the online version

If GitHub Pages is enabled for this repository, just open the URL in your phone's browser:

```
https://wowful368.github.io/grid-splitter/
```

That's it. No download, no unzipping, no risk of missing files. This is the easiest option and
the recommended one.

To enable it (one-time, ~2 minutes): go to **Settings → Pages**, set **Source** to
`Deploy from a branch`, choose branch **`main`** and folder **`/ (root)`**, then save.

### Alternative: offline use from the ZIP

Download `grid-splitter-web.zip` from the Releases page and transfer it to your phone
(send it to yourself via a messaging app, or use cloud storage).

> [!WARNING]
> **Do not transfer `index.html` on its own.** The web version needs all three of these files,
> and the folder structure must be preserved, or you will get a blank page:
>
> ```
> index.html
> app.js
> vendor/fflate.umd.js
> ```

Steps:

1. Unzip the archive on your phone (your file manager, or an app like ZArchiver)
2. Locate `index.html` in the extracted folder
3. Long-press it → **Open with** → choose a browser (Chrome, Edge, Firefox, etc.)

If you get a blank page, that is your browser restricting local file access — a security policy,
not a broken file. Try a different browser, or use the online version above instead.

### What to expect on a phone

| Aspect | Notes |
|---|---|
| Selecting images, splitting, exporting ZIP | Works normally |
| Square / ratio cropping | Works normally |
| Dragging the crop box | Works with touch, but a finger is less precise than a mouse for small boxes |
| Very large images | Phone memory is limited; images above roughly 8000 px may lag or fail |


## CLI version

Requires Node.js 14 or later. Install dependencies first:

```bash
npm install
```

### Usage

```bash
node slice.js <image...> [options]
```

### Examples

```bash
# 2x2 equal split
node slice.js photo.jpg -r 2 -c 2

# 3x3 split, lossless PNG output to a specific directory
node slice.js photo.jpg -r 3 -c 3 --png -o ./out

# Crop first (x,y,w,h), then split 2x2
node slice.js photo.jpg --crop 100,200,1000,800 -r 2 -c 2

# Custom ratios: columns 1:2:1, rows 1:1
node slice.js photo.jpg --col-ratio 1,2,1 --row-ratio 1,1

# Fixed 1080x1080 tiles, including the leftover edges
node slice.js photo.jpg --tile 1080x1080 --remainder

# Custom file names
node slice.js photo.jpg -r 2 -c 2 \
  --prefix "tile_" --name "{base}_r{row}c{col}_{w}x{h}"

# Batch process several images with the same parameters
node slice.js a.jpg b.jpg c.jpg -r 3 -c 3 --png -o ./out
```

### All options

| Option | Description |
|---|---|
| `-r, --rows <n>` | Number of rows |
| `-c, --cols <n>` | Number of columns |
| `--col-ratio <list>` | Column width ratios, e.g. `1,2,1` |
| `--row-ratio <list>` | Row height ratios, e.g. `1,1` |
| `--tile <WxH>` | Fixed pixel size, e.g. `1080x1080` |
| `-o, --out <dir>` | Output directory; defaults to `<name>_切片` next to the image |
| `--crop <x,y,w,h>` | Crop before splitting (pixel coordinates) |
| `--png` / `--jpg` | Lossless PNG / JPEG output (JPEG by default) |
| `-q, --quality <50-100>` | JPEG quality, default 92 |
| `--remainder` | In fixed-size mode, also output the leftover edges |
| `--name <template>` | Naming template, default `{base}_r{row}c{col}` |
| `--prefix <prefix>` | Filename prefix |
| `--quiet` | Print a summary only |
| `-h, --help` | Show help |

Naming template placeholders: `{base}` original name, `{row}` row number, `{col}` column number,
`{w}` tile width, `{h}` tile height, `{n}` sequence number.

## About "even" splitting

When the image dimensions are not divisible by the row/column count (e.g. width 1773 split into
2 columns), the remainder is distributed across tiles using cumulative rounding, so tile sizes
differ by at most 1 pixel:

- width 1773 into 2 columns → `887` + `886`
- width 1773 into 3 columns → `591` × 3
- width 1773 into 4 columns → `443` + `443` + `443` + `444`

The tile sizes **sum exactly** to the original dimensions — no gaps, no overlap. The web and CLI
versions share the same algorithm, so the same image with the same parameters produces identical
tile sizes in both.

## Technical notes

- **Web version** has no external dependencies. The ZIP library
  [fflate](https://github.com/101arrowz/fflate) is bundled in `vendor/`, so it works fully offline.
- **CLI version** uses [sharp](https://sharp.pixelplumbing.com/) for image encoding/decoding —
  no format parsing was hand-written.
- **Losslessness guarantee**: each CLI tile is decoded directly from the source file and cropped,
  with no intermediate format round-trip. (Calling sharp's argument-less `toBuffer()` re-encodes
  in the source format, which for a JPEG source means a second lossy compression pass — this is
  deliberately avoided.)
